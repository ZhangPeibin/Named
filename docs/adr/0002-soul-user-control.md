# ADR 0002: Soul 由用户控制

- **Status:** Accepted
- **Date:** 2026-11-20
- **Deciders:** 产品 / 客户端 / 后端
- **Related:** PRD §5.10、§5.11；`docs/feature/v1/loop-closure/discussion.md`

## Context

Soul 承载对用户背景、兴趣与相关经历的持续理解，用于让 Talk 更贴近这个人的切入点。后端已经具备完整能力：

- `GET/PATCH /soul` 读取与修改 profile。
- `POST/PATCH/DELETE /soul/items` 管理条目。
- 每条 item 带 `source`（如 `onboarding`、`user_edit`）。
- 删除为软删除，账号删除时清理。

但客户端没有暴露这些能力：用户看不到 Soul 里存了什么，也无法删除。与此同时，Talk 会把 Soul item 与来源一起注入 prompt（`talk/service.py`）。结果是「系统知道关于我的事，但我无法查看或否认它」。

闭环的 Reuse 环节依赖 Talk 知道用户背景；而用户只有在能看见、能删除的前提下，才会允许这种记忆存在。所以 Soul 控制不是附加功能，是 Reuse 的信任前提。

## Decision

1. **可见。** 用户可以看到每一条 Soul item 及其来源（初始引导 / 用户填写 / AI 提炼）。
2. **可改。** 用户可以编辑、删除、新增条目；删除为软删除并立即从 prompt 中消失。
3. **会话级开关。** 每个会话有 `use_memory`（默认开启）；关闭后该会话不注入任何 Soul item。
4. **全局提炼开关。** 用户可以关闭自动提炼；关闭后不再自动写入 AI 提炼项。
5. **不做逐条审批。** 提炼项立即生效，但保持可见、可删，并在 UI 中标注来源。
6. **不得复述为用户事实。** AI 提炼项可以影响话题选择，但 prompt 必须禁止把它说成用户已经讲过的事实。

## Consequences

正向：

- 用户可以纠正或删除过时、错误或不想被记住的信息。
- 会话级开关让用户在不删除长期记忆的情况下进行「干净」的对话。
- 来源标注满足 PRD 「AI 内容与用户经历必须可区分」的要求。

代价与风险：

- 新增 `Conversation.use_memory` 字段与迁移，需要覆盖旧会话默认值。
- 若自动提炼路径尚未实现，全局开关暂时没有作用对象；必须先确认写入路径，避免做出一个无效开关。
- 用户删除条目后，历史 Experience 仍保留原始对话，可能出现「Soul 已删但历史仍可查」的预期差，需要在文案中说明。

## Alternatives considered

1. **逐条审批（AI 提炼项先进 pending）。** 否决：打断交流、增加摩擦，与「不把每次对话变成固定教学脚本」冲突。
2. **只读展示。** 否决：用户能看见但不能删，信任问题没有解决。
3. **不做会话级开关，只做全局。** 否决：用户常需要「这次先不带记忆」，全局开关代价过高。
