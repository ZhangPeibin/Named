# ADR 0001: 闭环靠状态而非知识图谱

- **Status:** Accepted
- **Date:** 2026-11-20
- **Deciders:** 产品 / 客户端 / 后端
- **Related:** PRD §3.5、§4、§5.5；`docs/feature/v1/loop-closure/discussion.md`

## Context

PRD V1.0 把 Knowledge graph 列为三大支柱之一，用来把 Word、场景、图片、表达与对话连接起来。实现过程中先落地了 Discover、Talk、Review、Challenge 与 Soul，知识图谱尚未实现。

在没有图谱的情况下，学习闭环暴露出四个问题：

1. Review 取词随机，用户无法预期今天复习什么。
2. Review 先给英文词、再看中文释义，练的是识别与翻译。
3. 复习结果只写回 `review_count`，用户看不到词发生任何变化。
4. Timeline 上有四种以上「回来做事」的提示，但没有唯一入口。

问题的实质不是「内容之间缺少链接」，而是「一次学习没有回到起点并留下可见变化」。图谱解决横向检索，不解决纵向回归。

## Decision

**用状态闭合闭环，把图谱降级为后续增强。**

1. 每个词对每个账号有生命周期：`needs_review → attempted → growing → known`，状态由已有的 `WordProgress` 与新的尝试字段计算。
2. 复习方向翻转：先要求用户产出，再提供提示阶梯，最后揭晓答案；用户自评，不做读音评分。
3. 返回入口唯一：Timeline 顶部「今天要见的词」，其余提示降级。
4. 尝试与使用写入 `WordProgress`（`attempt_count`、`last_attempt_at`、`used_count`、`last_used_at`），作为闭环证据与排序依据，不作为分数。
5. 闭环的可见性标准：第 1 天发现的词，第 7 天在 Timeline 上因用户自己的行为而不同。

「先开口，再给答案」作为配套原则：不给句子，只给词；未知单词可以直接给，整句必须由用户先尝试。

## Consequences

正向：

- 闭环可以在没有图谱的情况下交付并验证，减少一次性投入。
- 状态是单表字段，迁移成本低，容易测试。
- 复习方向翻转让最薄弱的一环（产出）进入主路径。
- 单一入口让「回来做什么」有明确答案。

代价与风险：

- 语言关联能力短期缺失；用户只能按词或时间找回内容，不能沿关联浏览。
- 状态需要精确定义，否则会变成隐性的掌握度评分。文案必须避免「掌握」。
- 复习产出依赖用户自律；不做 ASR 评分意味着无法验证读音，只能依赖自评。
- `used_count` 的匹配规则若过宽（如 `can` 命中 `candle`）会污染证据。
- 键盘与语音两种尝试方式都需要支持，否则零基础或不便打字的用户被排除。

## Alternatives considered

1. **先做知识图谱，用关联驱动闭环。** 否决：图谱是浏览能力，用户仍需自己决定何时回来；无法解决「没有唯一返回入口」与「复习方向错误」。
2. **引入间隔重复算法。** 否决（本阶段）：PRD §12 已把完整 SRS 排除在首版外；三态加 7 天窗口足以先验证闭环是否成立。
3. **用导航串联六个页面（发现 → 词 → 对话 → 复习）。** 否决：导航只能提示路径，不能制造回归；用户不会主动走完六页。
4. **给复习结果打分并累计正确率。** 否决：与「不宣称掌握」冲突，且自评分数没有意义。
