## 1. 产品定位

**Named 是一个从真实生活出发，通过 AI 对话帮助用户理解、表达、记忆并持续使用英语的学习产品。**

产品以 **Name everything you see** 为起点：用户遇见一个事物或场景，发现自己不知道如何用英语表达，便可以从这里开始学习。

Named 的目标是让词语与用户的真实经历、交流和记忆建立联系，逐渐形成个人英语知识与表达能力。

### Personal English World

**从真实生活出发，建立自己的英语世界。**

Personal English World 是用户在 Named 中持续建立的个人英语世界。每个词或场景都可以连接真实发现、个人交流、相关知识和学习历程，随着新的经历与使用不断丰富。

以 **Tree（树）** 这个词为例，它可以同时连接：

| 维度 | 用户关心的问题 | 示例 |
| --- | --- | --- |
| **Discovery** | 在哪里发现它？ | 在公园遇见的一棵树、拍下的照片、当时记录的事情 |
| **Conversation** | 围绕它说过什么？ | 和 AI 谈这棵树的外观、树荫或一次公园散步的经历 |
| **Knowledge** | 关联了哪些知识？ | leaf、branch、trunk，相关语法、描述句子与场景表达 |
| **History** | 自己怎样逐渐理解和使用它？ | 第一次发现、最初的表达、之后的回看、新对话和再次使用 |

此例用于说明关联结构，不预设为用户真实发生过的经历。Discovery、Conversation、Knowledge、History 是理解与组织个人内容的四个维度，具体页面与导航仍待设计。

同一个 Tree 可以连接多次发现和多段交流；同一场景或对话也可以连接多个词。用户能够沿着这些联系，从一个词走向更丰富的个人英语世界。

### 三个定位支柱

| 支柱 | 产品含义 | 对功能设计的要求 |
| --- | --- | --- |
| **Context-first learning** | 从用户真实接触的生活场景、事物和经历开始学习 | 用户可从眼前的照片或描述直接开启理解与交流，学习内容围绕真实情境展开，无需先进入预设课程 |
| **Personal conversation history** | 对话成为可不断回访、继续和拓展的个人资产 | 保存完整交流及相关背景，让用户能找回、复习、续聊，并积累新的经历与表达 |
| **Knowledge graph** | 把单词、场景、图片、表达和历史对话连接起来 | 保留内容之间的关联，让用户能够从一个词、一个场景或一段对话进入相关内容，延续个人学习 |

三者共同构成产品结构：**真实情境提供起点，个人对话承载经历，知识图谱连接积累。** Challenge 为这些内容提供阶段性组织方式。

### 核心理念

> **Don’t just learn a word. Build a relationship with it through real experiences, conversations, and memories.**

不要只是学会一个单词。通过真实经历、对话与记忆，逐渐与它建立联系。

## 2. 用户问题与预期结果

### 2.1 用户问题

- 生活中不断遇到不会用英语描述的事物和场景。
- 查询到单词后，仍不清楚如何发音、理解和使用。
- 单独的释义和例句缺少个人关联，难以留下深刻记忆。
- 希望围绕自己感兴趣的内容交流，却缺少能自然回应的英语伙伴。
- 有价值的交流容易散失，之后难以回看或接着聊。
- 学习内容分散，难以形成持续积累。
- 单词、场景、图片与对话分散保存时，难以找回它们之间的联系和当时的学习背景。

### 2.2 预期结果

用户可以从一个真实发现开始，理解相关英语，通过交流尝试表达，并保留自己的学习经历。以后再次遇见这个词或场景时，能够找回相关内容和对话，在已有理解上继续使用。

已有亲子 Weekly Game 是具体需求来源之一：发现家庭物品、选出学习内容、查询与书写英文，再于后续几天寻找实物、反复听读。成人独立学习同样属于产品支持的使用情境，不能以某个家庭或某位孩子的情况代表全部学习者。

## 3. 核心产品原则

### 3.1 Every word has its own story

每个词都有自己的故事。**用户的真实经历是故事的基础：**

- 在哪里遇见它。
- 为什么注意到它。
- 它与什么人、事情或感受有关。
- 用户围绕它说过什么。
- 后来又发生了什么。

AI 可以通过相关故事、例子、文化背景和想象情境丰富理解，但必须区分：

1. 用户分享的真实经历。
2. AI 提供的解释和知识。
3. AI 创作的故事或假设情境。

AI 不得把自己生成的故事记录为用户经历。

例如，用户在祖母的花园里发现洒水壶，并分享帮祖母给番茄浇水的经历。这是 watering can 的个人故事基础。AI 可以帮助描述这段经历、解释相关表达或讲一个相关故事，之后也可以基于这段已知经历继续交流。

### 3.2 AI 应像自然的交流伙伴

AI 应关注用户在说什么、想表达什么，并作出相关、有上下文的回应。

- 顺着用户的兴趣交流，提出相关的问题。
- 自然地解释词语和帮助表达。
- 不把每次对话都变成固定教学脚本。
- 不因每个小错误持续打断交流。
- 在需要时提供清楚、具体的纠正与改进表达。
- 在延续旧对话时，使用相关历史背景。
- 信息不足、未听清或无法确认时，明确表达不确定。

### 3.3 简单英语与母语共同支持理解

两者都是核心能力：

- **简单英语**：帮助用户建立英语理解与表达。
- **用户母语**：清楚解释含义、语法、使用方式及必要区别。

母语解释不是仅在理解失败时才出现的补救能力。具体展示和语言切换方式在交互设计中确定。

### 3.4 内容与学习经历属于个人

不同学习者可以复用基础语言知识，但其发现、个人故事、对话与学习记录应独立保存。

一次听读、一次正确回答或一次挑战完成，不直接等同于掌握。

## 4. 核心学习闭环

**Discover → Talk → Understand → Save → Review → Reuse**

| 环节 | 用户行为与产品支持 |
| --- | --- |
| Discover | 从真实生活发现一个事物、词语或场景，通过拍照或文字开启学习 |
| Talk | 围绕它与 AI 自由交流 |
| Understand | AI 使用简单英语和用户母语，帮助理解、组句和表达 |
| Save | 自动保存完整对话，语音交流留下可阅读的文字记录 |
| Review | 随时回看历史对话，在上下文中复习 |
| Reuse | 基于过去的对话和经历继续交流，让学习持续深入 |

这些环节可以自然往返，不要求用户每次执行固定步骤。

## 5. 核心功能

### 5.1 Discover：发现与认识

用户可以拍摄真实事物或场景，也可以输入名称、描述或想表达的内容。AI 根据输入帮助识别和理解，并返回对应的英语学习内容。

#### 功能要求

- 支持单个物品，也支持生活场景。
- Discover 本身能产生学习价值，不只是保存一条待处理记录。
- 不要求先创建 Challenge 才能使用。
- 图片有多个对象、名称有歧义或描述不完整时，应帮助用户确认具体所指。
- 保留用户输入与后续确认的背景，作为个人故事的来源。
- 不要求每次发现都填写地点、时间或完整经历。
- AI 延伸出的内容与用户真实发现应有明确区别。

### 5.2 Word：核心学习单元

| 能力 | 功能要求 |
| --- | --- |
| 图片 | 呈现对应事物或帮助理解的情境 |
| 文字 | 展示英文名称和拼写 |
| 语法 | 解释适用的词性、变化与使用规则 |
| 听读 | 播放发音，支持不同速度及重复听读；音标和英美发音信息辅助理解读音 |
| 双语理解 | 提供简单英语解释与用户母语解释 |
| 组句 | 帮助用户用这个词组织句子、表达自己的意思 |
| 场景引申 | 关联相关动作、词语、表达和生活情境 |
| 对话 | 进入围绕该词或相关场景的 AI 交流 |
| 故事与历史 | 找回相关发现、个人经历和历史对话 |

这些内容应围绕用户当前的理解与表达需要组织，不要求全部一次性展开。

场景发现可以关联多个 Word；场景也可以直接成为对话背景，不必强行缩减成单个名词。

### 5.3 Talk：围绕词语或场景交流

用户可以通过语音或文字，与 AI 自由交流。例如从 watering can 开始，谈到在哪里看见它、家里种了什么植物、如何描述浇水，以及与家人一起照顾植物的经历。

#### 功能要求

- 理解和回应用户实际表达的内容。
- 允许用户提问、尝试表达、请求解释和自然延伸话题。
- 支持词语、句子、经历和场景层面的交流。
- 提供必要的示范、慢速听读及表达帮助。
- 发音反馈必须有实际语音依据；不能仅凭转写文本编造读音评价。
- 未听清时，请用户确认或重试。
- 用户可以暂停或结束当前交流。

#### 对话页面的基本结构

- **顶部：虚拟人物。** 建立面对一个交流伙伴的感受，与自然对话体验配合。
- **下半部：对话内容。** 呈现用户与 AI 的交流文字，方便边听边看和理解。
- **底部：对话控制。** 放置开口、输入及相关交流操作，具体按钮与收音方式仍需设计。

虚拟人物的形象、静态或动态表现、画面占比与技术实现尚未确定。

#### 常用表达与词语标注

- 在对话内容中突出常用句子、表达或相关单词，帮助用户注意到可再次使用的语言。
- 标注保留完整交流的上下文，用户能够知道该表达是在什么情境下出现的。
- 标注内容可以与对应 Word、Expression 和 Conversation 建立关联，支持后续回看与复用。
- 语言标注与错误纠正分别表达，避免把常用表达的强调误解为用户说错。
- 标注由 AI 提取、用户主动选择或两者结合，以及点按后的具体操作，留待设计确认。

### 5.4 Conversation History：自动保存与回看

系统自动保存用户与 AI 的完整对话，供以后阅读和继续交流。历史对话应包含：

- 用户与 AI 的发言及先后顺序。
- 语音交流对应的文字转写。
- 关联的词语或场景。
- 用户原始表达。
- 与原始表达分开呈现的纠正和改进建议。
- 延续交流所需的相关背景。

对话是可以不断回访、继续和拓展的个人学习资产。用户可以由相关词语、场景或图片找回原交流；在后续交流中积累的新内容，继续与这些背景建立关联。

#### 记录原则

- 不能用改写后的正确表达覆盖用户原话。
- 语音转写是识别结果，不能假定永远准确；不确定内容的确认方式需设计。
- 保存文字历史不等于默认长期保存原始录音。
- 用户能够找回对话并阅读完整上下文。
- 自动保存失败或尚未完成时，应有明确状态，不能误导用户认为已经保存成功。

完整对话保存后，系统还应自动提炼其中的个人经历和实际学习经历，形成可关联、可回访的 Experience，并持续丰富 Soul。完整交流、提炼后的经历和个人背景相互关联，浓缩不覆盖原始对话。

### 5.5 Review：通过历史对话加深记忆

用户可以回到词语、场景或历史交流，重新阅读自己参与形成的内容。复习重点包括：

- 当时想表达什么。
- 自己是怎么说的。
- AI 如何回应。
- 有哪些更清楚、自然的表达。
- 这个词与自己的什么经历有关。

首版以历史对话回看、相关内容听读和再次交流为基础复习方式。其他题型与自动复习安排另行确定。

### 5.6 Reuse：基于历史继续交流

用户可以从一段历史对话继续，而不必重新交代全部背景。

- 能够从已有对话进入继续交流。
- AI 使用相关历史上下文作出回应。
- AI 可以结合提炼的相关 Experience 和持续丰富的 Soul 延续交流，并能够回到原始对话取得具体背景。
- 新交流与原有经历保持可理解的联系。
- 继续产生的内容纳入可回看的历史。
- 历史未记录或无法确认的信息，不得当作已知事实。
- 用户提供新情况时，应尊重更新后的信息。

对话续接的具体分段、展示和历史组织方式留待交互设计。

### 5.7 Challenge：组织一轮持续学习

Challenge 将用户选择的一组内容组织起来，帮助其持续学习与练习。它是 Named 的一种学习组织方式，不定义产品的全部能力。

- 支持开始新的 Challenge。
- 支持继续进行中的 Challenge。
- 用户可以选择学习内容与数量。
- 周期不固定为一周，可以两天、一周或其他安排。
- 保留历史 Challenge，能够回顾和再次使用相关内容。
- 集合结束不删除相关 Word、故事或对话。
- 挑战进度与长期掌握情况分别表达。
- AI 可以建议内容关联或组织方式，最终选材由用户或协助者决定。

Weekly Game 是已有实践。产品通用名称使用 **Challenge**，不把按周安排写成系统限制。

### 5.8 Personal English World：个人积累与成长

用户能够持续找回自己的发现、相关 Word 和场景、分享过的个人经历、历史对话及表达建议、当前与历史 Challenge，以及学习和练习记录。

这些内容共同构成 Personal English World，通过 Discovery、Conversation、Knowledge、History 四个维度找回和理解。

#### History：自己的成长轨迹

- 能够回顾一个词或场景的首次发现、相关交流、回看和后续使用。
- 保留不同时点的原始表达，以及对应的纠正与改进建议，让用户看见自己曾经如何表达、后来又如何尝试。
- History 汇集有记录依据的发现与学习历程；完整交流内容由对应的 Conversation 承载。
- 成长通过实际经历与表达的变化体现，不因记录次数增加就自动宣称已经掌握。

具体是否拆分为独立知识库、故事页或时间线等页面，留待原型设计。

### 5.9 Knowledge Graph：连接个人学习内容

知识图谱连接个人的 **Word、Context／场景、Picture／图片、Expression／表达、Conversation／历史对话与 Experience／经历**，保留这些内容与真实发现和个人经历的联系。

#### 关联的业务含义

| 关联 | 示例 |
| --- | --- |
| 场景与单词 | 用户在祖母花园的场景中接触 watering can、tomato、plant |
| 图片与场景／单词 | 某张发现照片呈现洒水壶，并记录其所处的花园背景 |
| 单词与表达 | watering can 关联 water the plants 及用户实际尝试过的句子 |
| 对话与单词／场景／表达 | 一次交流讨论洒水壶、浇番茄和用户帮助祖母的经历 |
| 经历与对话／知识 | 从该次交流提炼的个人经历连接原对话、watering can、浇水表达和相应场景 |
| 历史与后续交流 | 后续对话继续谈论同一经历的发展，并连接新增的表达 |

以上是用户提供了相应经历时的示例，不预设为任一学习者的真实记录。

#### 用户可获得的能力

- 从一个词找到相关场景、图片、表达和历史对话，理解它与自己的关系。
- 从一个场景找到其中涉及的词语、表达和个人交流。
- 从历史对话回到相关词语与场景，并基于这些背景继续拓展。
- 对话涉及多个词或场景时，保留相应关联，不将其孤立在一个词的页面中。
- 持续发现与交流时，扩展既有内容关联，使不同次学习能够连接起来。
- 围绕一个词连接多次发现与交流，并将相关事件纳入个人 History，支持回顾它如何在用户的生活与表达中逐渐丰富。

#### 关联原则

- 个人经历相关的关联属于相应学习者；共享基础语言知识不能合并不同人的经历。
- 能区分来自用户输入／对话的经历关联，以及 AI 提供的语言关联或想象情境。
- 知道一个词与某动作有关，不代表用户实际做过这个动作。
- 内容来源、关系类型、重复词义和归档规则在数据与交互设计阶段明确。

此处定义的是内容关联与找回能力。图形化展示方式、数据库选型与自动关联机制仍待设计。

### 5.10 Soul：轻量引导与持续形成的个人理解

用户首次进入时，以简洁引导建立对这个人的初步了解。之后，系统从对话中自动提炼用户经历，持续丰富 Soul。Soul 承载对用户背景、兴趣、偏好及相关经历的理解，帮助 AI 在具体词语和场景中选择更贴近用户的切入点、追问及表达方式。

#### 已明确要求

- 引导保持轻量，服务于开始交流，避免繁重的信息填写过程。
- 引导采用少量分步问题，了解兴趣、年龄、性别、母语和少量日常背景。每一步突出一个主题，不要求写长篇自我介绍。
- 记录对话所需的个人背景，让 AI 初次交流时就能有所依据。
- 年龄与性别作为用户提供的背景保存，不据此直接推断英语水平、兴趣或生活经历。
- AI 结合 Soul、当前发现或场景，以及相关历史进行交流，保持对当前话题的关注。
- Soul 中的个人背景以用户提供的信息为依据，不从一个词或一张照片推断未经表达的人生经历。
- 个人具体经历仍关联原始发现与对话，供用户回看和继续使用。
- 自动从后续对话中提炼用户明确分享的经历与个人信息，更新相应的 Experience 并持续丰富 Soul。
- 新情况可能补充或改变已有理解；更新时保留具体经历的背景，不把用户过去某时的情况无限延用到现在。

#### 待确认的内容与规则

- 原型以四步呈现：兴趣 → 年龄 → 性别 → 母语与一句日常介绍，提供跳过、返回和后续修改；具体问题、选项和必填范围仍可调整。
- Soul 的个人信息查看、补充或修改细节。
- 自动提炼的具体时机、信息粒度，以及重复、矛盾和信息变化的处理方式。

Soul 与 Word、场景和历史对话共同支持个性化交流，不改变 Context-first 的学习起点。

### 5.11 Experience：将对话浓缩为用户经历

每段对话都参与经历提炼，让交流逐渐沉淀为用户自己的经历和学习历程。

- **个人生活经历**：用户明确分享的真实接触、事件、关系或感受，保留用户实际提供的背景。
- **实际学习经历**：用户在这次交流中讨论、尝试表达、理解或练习了什么。

例如，用户分享“今天在公园看见一棵树，和女儿在树荫下休息”，并练习了 under the tree。这次交流可以浓缩为相应的生活经历及表达练习，关联 Tree、公园场景、under the tree 和原对话。此例仅说明提炼方式。

#### 功能要求

- 自动提炼，不要求用户为每次对话手工写总结。
- 每条经历可关联来源对话及相应词语、场景、图片和表达，供回看、续聊和个人 History 使用。
- AI 根据当前话题使用相关经历，持续形成对这个人的理解。
- 提炼内容保留用户原意，不能添加用户未提供的事件、地点、人物或感受。
- 交流中的练习句、意愿、假设和 AI 故事应保留其性质：练习说过“我去了公园”，只能据此记录表达练习，不能直接推断用户实际去过公园。
- 用户对既有情况的更正应反映到后续提炼与交流所使用的理解中；完整原始对话继续保留。

Experience 记录具体发生或分享过什么，Soul 汇集对用户的持续理解，Conversation 保留交流原文。三者共同支持有依据的个性化对话。

## 6. 入口与用户状态

产品主要入口为：

1. **Discover new things**
2. **Start a new challenge / Continue**

入口内容根据实际学习状态调整。新用户首先获得轻量引导，建立供 AI 交流使用的初始 Soul；引导的具体步骤和必填范围待确认。

| 用户状态 | 主要支持 |
| --- | --- |
| 新用户，没有个人内容 | 经轻量 Soul 引导后，通过拍照或文字完成首次 Discover，理解产品价值，并能够开始第一次 Challenge |
| 有进行中的 Challenge | 明确提供 Continue，同时保留 Discover 和开始新 Challenge 的入口 |
| 已有积累，当前没有进行中的 Challenge | 开始下一轮、回看历史内容，或从旧对话继续交流 |

“新用户”“进行中”“已有积累”是使用状态，不单纯由注册时间或年龄判断。

## 7. 核心用户故事

1. 作为学习者，我希望拍照或输入真实事物，让 AI 帮助我知道如何用英语描述它。
2. 作为学习者，我希望通过图片、听读、语法以及两种语言的解释，理解词语及其用法。
3. 作为学习者，我希望围绕自己的经历与 AI 自由交流，练习真实想说的话。
4. 作为学习者，我希望原始表达和改进建议分别保留，方便回看自己的尝试。
5. 作为学习者，我希望对话自动保存，避免丢失有价值的学习内容。
6. 作为学习者，我希望回看旧对话并接着交流，让词语与经历不断建立联系。
7. 作为学习者，我希望根据自己的节奏组织 Challenge，并随时继续。
8. 作为需要协助的学习者，我希望有人可以帮助选材和操作，同时保留独立的个人学习记录。
9. 作为学习者，我希望单词、场景、图片、表达和对话互相关联，方便找回它们与自己经历的联系，并继续学习。
10. 作为新用户，我希望通过简单引导让 AI 初步了解自己，获得更贴近个人背景的交流。
11. 作为学习者，我希望看到对话中的常用句子与相关单词，方便理解、回看和再次使用。
12. 作为学习者，我希望对话自动浓缩为自己的经历，让 AI 随交流更了解我，并能结合过去的真实背景继续交流。

## 8. 第一版交付范围

第一版以手机端实现两个核心入口，并完成学习闭环：

- 拍照或文字 Discover。
- AI 返回相应的词语或场景学习内容。
- Word 的图片、文字、语法、变速听读、双语解释、组句及场景引申。
- 围绕词语或场景的 AI 语音与文字交流。
- 少量分步的 Soul 引导，收集兴趣、年龄、性别、母语及简短日常背景，并从后续对话自动提炼经历、持续丰富 Soul；必填范围和更新细节待设计。
- 顶部虚拟人物、下半部内容及底部对话控制的基本页面结构，以及对话中的常用表达／词语标注。
- 完整对话自动保存，保留原始表达与独立的改进建议。
- 将对话自动浓缩为用户的生活／学习经历，关联原对话、相关知识与个人 History。
- 历史对话回看及基于历史继续交流。
- 开始、继续和回顾 Challenge，支持非固定周周期。
- 个人内容持续积累。
- 建立单词、场景、图片、表达与历史对话的基础关联，并支持沿关联找回内容。
- 新用户、进行中用户和已有积累用户的对应入口状态。

纸质笔记可以继续作为个人学习习惯的一部分，不是使用产品的前置条件。

## 9. 成功与验收标准

| 验收场景 | 可观察的结果 |
| --- | --- |
| 首次发现 | 用户通过照片或文字获得相关英语内容，无需先创建 Challenge |
| 含糊输入 | AI 帮助确认所指，不把不确定识别当成确定事实 |
| 理解词语 | 简单英语与用户母语两种解释均可获得，听读支持不同速度 |
| 自然交流 | AI 回应用户实际内容，能接续话题、帮助表达，不只执行固定脚本 |
| 个人背景 | 用户通过简洁引导提供背景后，AI 能结合已知信息与当前话题交流，不编造用户未提供的经历 |
| 经历浓缩与 Soul 更新 | 对话中的真实分享与实际学习内容自动形成关联经历，原文仍可回看；后续交流可以使用这些背景，假设或练习句不会被当成实际生活事件 |
| 对话页面 | 用户能看见虚拟人物、阅读交流文字，并找到底部对话操作 |
| 语言标注 | 常用句子／词语在原对话上下文中可辨认，并可在后续回看时找到相关内容；标注与错误纠正可区分 |
| 个人故事 | AI 能基于用户分享展开，同时区分真实经历与创作内容 |
| 对话保存 | 重新进入历史后，可以看到已成功保存的完整交流和独立纠正 |
| 历史延续 | 用户从旧对话继续时，AI 能利用相关已知背景 |
| 内容关联 | 用户能从一个词找回相关场景、图片、表达和历史对话，也能从场景或对话回到相关词语 |
| 关联真实性 | 用户经历关联与 AI 语言建议／创作可区分，不将推测关系当作用户实际经历 |
| 周期安排 | 用户可以组织非一周周期的 Challenge，并继续进行中的学习 |
| 长期积累 | Challenge 结束后，相关内容与历史对话仍可找到 |
| 个人英语世界 | 用户能围绕同一个词找回 Discovery、Conversation、Knowledge、History，理解其生活来源、交流内容、知识关联及学习历程 |
| 学习记录 | 初学、练习和挑战完成不会被自动等同于掌握 |
| 异常处理 | 识别、生成、语音或保存失败时，用户能够分辨状态并获得重试或继续入口 |

产品效果还应通过真实使用观察：

- 用户是否愿意主动发现和开口。
- 是否能够表达自己的实际经历。
- 是否回看、复用历史对话。
- 是否在真实生活中再次使用学过的表达。

具体量化指标不在缺少使用证据时预设。

这些事项不影响产品定位定稿，但会阻塞对应部分的详细设计或开发。

| 语音体验 | 验证收音、结束发言、转写确认和慢速播放，产出可体验样例；明确纠音依据与容错 |

| Experience 提炼 | 确定浓缩时机、信息粒度、来源关联、重复经历处理及提炼失败的恢复方式；验证生活事实、学习行为与假设情境的区分 |
| 对话页与虚拟人物 | 确定人物形态、状态表现、内容区域及底部控制；动态或静态实现尚未决定 |
| 语言标注 | 明确 AI／用户的标注方式、常用表达的选择依据、点按操作及其与个人知识的关联规则 |
| 保存与恢复 | 确定自动保存时机、失败重试和中断恢复行为 |
| 账号与协助 | 明确个人身份、学习者切换、家长或引导者的访问权限 |
| 数据管理 | 明确历史删除、保留规则及是否保存原始录音 |
| 技术与运行条件 | 确定客户端、AI 与语音服务、网络要求和离线边界 |

## 11. 验证策略

优先验证完整的用户行为链路：**发现 → 理解 → 交流 → 自动保存 → 回看 → 继续交流。**

实现时应覆盖：

- 图片与文字 Discover 的正常及含糊输入。
- Word 内容、双语解释与变速听读。
- Challenge 创建、继续和历史回顾。
- 对话原话、转写、纠正与改进建议的区分。
- Soul 已知背景对交流的影响，以及语言标注保留原上下文、与纠正的区分。
- 对话自动提炼经历、关联原文并更新后续交流背景；验证练习句／AI 故事不生成虚假生活事实，以及用户更正后的更新。
- 保存后重新进入及历史上下文续聊。
- 从单词、场景或对话沿关联找回其他个人内容，以及同词不同学习者之间的经历隔离。
- 生成、语音、网络和保存异常。

测试应验证用户可观察的行为，不镜像内部实现。优先从端到端或产品服务边界覆盖整个学习闭环，避免将同一流程拆成大量仅验证内部细节的测试。

AI 的自然交流、事实区分和反馈质量，还需要通过真实对话样本进行体验评估。当前项目包含产品文档和可交互的高保真设计样例，尚无正式客户端／服务端或既有应用测试基础；具体技术、测试边界与工具在技术设计阶段确定。

## 12. 暂不纳入首版

- 完整课程、考试或职场专项体系。
- 社交排行榜和复杂游戏化。
- 完整的间隔复习算法与多种练习题库。
- 扫描纸质 Notebook 的完整流程。
- 不以用户发现或相关场景为基础的独立泛聊天产品。
- 未经确认的自动掌握判定。
- 将 AI 创作的故事自动记为用户经历。

## 13. 对旧版定义的更新

本版取代旧 PRD 中以下约束：

- 正式产品名称确定为 **Named**。
- Discover 支持拍照和文字，并直接提供 AI 学习价值。

- 学习组织由固定 Weekly Game 调整为周期可安排的 Challenge。

- 简单英语与用户母语共同构成理解支持。
