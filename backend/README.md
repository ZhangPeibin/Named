# Named Backend

FastAPI backend for Named. It uses FastAPI, SQLAlchemy async, MySQL, Alembic,
Pydantic AI, Qwen TTS, and DashScope speech recognition.

## Quick start (local)

Requirements: Python 3.12, [uv](https://docs.astral.sh/uv/), and Docker.

```sh
cd backend
cp .env.example .env
uv sync --all-groups
docker compose up -d mysql
make migrate
make dev
```

- API: `http://127.0.0.1:8000`
- Swagger UI: `http://127.0.0.1:8000/docs`
- Liveness: `GET /health/live`
- Readiness (checks MySQL): `GET /health/ready`

Fill in `.env` before starting:

- `DEEPSEEK_API_KEY` for Discover and Talk.
- `DASHSCOPE_API_KEY` for Qwen TTS and speech recognition.
- `DASHSCOPE_WORKSPACE` and `DASHSCOPE_WEBSOCKET_URL` for the workspace where
  the TTS models are enabled.

## Run everything with Docker

```sh
cd backend
cp .env.example .env
# edit .env with real provider keys
make docker-up
```

`docker compose up --build` starts:

- `mysql` on `127.0.0.1:3306`
- `api` on `127.0.0.1:8000`

The API container applies Alembic migrations on startup and stores media in the
`media_data` volume.

Useful commands:

```sh
docker compose ps
docker compose logs -f api
make docker-down
```

The `.env` file is excluded from the Docker image by `.dockerignore`. Do not run
`docker compose config` in a context where its output will be shared; it expands
and prints environment values, including secrets.

## Configuration

Copy `.env.example` to `.env`. The most important settings:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | MySQL async URL. Compose overrides it to use the `mysql` service. |
| `AUTH_SECRET` | HMAC secret for verification codes. Change outside development. |
| `DEEPSEEK_API_KEY` | DeepSeek API key for the Discover and Talk agents. |
| `AI_MODEL` | Pydantic AI model string, e.g. `deepseek:deepseek-flash`. |
| `DASHSCOPE_API_KEY` | Alibaba Cloud Model Studio / Bailian API key for TTS. |
| `DASHSCOPE_WORKSPACE` | Workspace where the TTS model is enabled. |
| `DASHSCOPE_REGION` | Model Studio region, e.g. `cn-beijing`. |
| `DASHSCOPE_WEBSOCKET_URL` | TTS WebSocket endpoint for that workspace. |
| `TTS_MODEL` | Default `qwen-audio-3.1-tts-plus`. |
| `TTS_VOICE_US` / `TTS_VOICE_UK` / `TTS_VOICE_TALK` | Voice IDs; they must match `TTS_MODEL`. |
| `STT_MODEL` | DashScope speech-recognition model. |
| `STT_TIMEOUT_SECONDS` | Speech-recognition timeout. |
| `EXPERIENCE_DEBOUNCE_SECONDS` | Quiet period before asynchronous Experience extraction. |
| `EXPERIENCE_MAX_ATTEMPTS` | Experience job retry limit. |
| `EXPERIENCE_WORKER_ENABLED` | Run the in-process Experience worker. |
| `MEDIA_ROOT` | Local media directory. Compose uses `/app/media`. |
| `AUTH_DEV_LOG_CODES` | Development only: log verification codes. Keep `false` in production. |

### Qwen TTS notes

The WebSocket endpoint follows this shape:

```text
wss://<workspace>.<region>.maas.aliyuncs.com/api-ws/v1/inference
```

The voice must belong to the selected model. For example:

- `qwen-audio-3.1-tts-plus` → `longanfengyue_v3.1`, `longanlingxin_v3.1`,
  `longanhuan_v3.1`, `xunanchuan_v3.1`
- `qwen-audio-3.0-tts-flash` → `longanfengyue`, `longanyuanfei`, etc.

A mismatched voice returns
`InvalidParameter: [cosyvoice:]Engine error [411]: TTS speak operation failed`.
A key that does not belong to the workspace returns `403 Forbidden` or
`Model.AccessDenied`.

## API overview

All business routes are under `/api/v1`.

| Area | Endpoints |
| --- | --- |
| Auth | `POST /auth/code`, `POST /auth/verify`, `POST /auth/logout`, `GET /me`, `DELETE /me` |
| Soul | `GET /soul`, `PATCH /soul`, `POST /soul/items`, `PATCH /soul/items/{id}`, `DELETE /soul/items/{id}` |
| Discover | `POST /discoveries` (multipart text/image), `POST /discoveries/{id}/focus`, `GET /discoveries/{id}`, `DELETE /discoveries/{id}` |
| Word | `GET /words/{id}` |
| Media | `GET /images/{key}`, `GET /audio/{key}` |
| Talk | `POST /conversations`, `GET /conversations/{id}`, `POST /conversations/{id}/messages`, `POST /conversations/{id}/end`, `POST /conversations/{id}/help` |
| History | `GET /history`, `GET /experiences/{id}` |
| Audio | `POST /audio/transcribe`, `POST /audio/pronunciation`, `GET /audio/{key}`, `GET /images/{key}` |

Errors use `application/problem+json` with `code`, `status`, `detail`, and
`request_id`. Every response includes an `X-Request-ID` header.

## Development commands

```sh
make test           # pytest at the HTTP API boundary
make lint           # ruff check
make format-check   # ruff format --check
make format         # apply ruff fixes and formatting
make migrate        # alembic upgrade head
make migration      # create an autogenerated migration
make purge          # hard-delete accounts scheduled for deletion
```

Tests use SQLite and fake AI/TTS providers; they do not require MySQL or
provider API keys.

## Current scope

Implemented P0 foundation:

- Email-code authentication and opaque sessions
- Soul profile and items
- Text and image Discover with AI-generated Word content
- Qwen TTS word audio with caching
- Non-streaming Talk with corrections, annotations, auto-save, idempotency,
  assistant audio, Chinese-to-English hints, and voice transcription
- Asynchronous Experience extraction with durable jobs, source evidence,
  life/learning separation, and History list/detail
- Companion memory and recurring error profile
- Account deletion with a 30-day hard-delete purge command
- Problem+json errors, request IDs, rate limits, OpenAPI, end-to-end tests

Not implemented yet:

- Automatic Soul updates / `soul.md`
- Experience context injection into Talk/Help
- Challenge and Knowledge Graph / Personal English World pages
- Streaming Talk (SSE) and real-time full-duplex voice
- Production email delivery, S3/MinIO media storage, and deployment automation
- Age gate / parental consent

## Security notes

- Keep all secrets in `.env`; `.env` is gitignored.
- Never put real keys in `.env.example`.
- Rotate any key that has been exposed in terminal output, logs, or a shared
  `docker compose config` dump.
- Media is stored locally by default. Use private object storage for production.
- Rate limiting is in-memory and per process; use a shared store for multiple
  API instances.
